# ADR-0008: 依存更新に Dependabot を採用しエコシステムごとに集約する

- ステータス: 廃止（ADR-0009 により置換）
- 日付: 2026-08-24
- 関連: [Issue #14](https://github.com/Ries630/BlazorCleanShop/issues/14)

## 背景

このリポジトリは、6 個の `.csproj` に分かれた NuGet エコシステムと、ルートの
`package.json` / `package-lock.json` で管理する npm エコシステムを持つ。直接参照は
NuGet が 7 パッケージ、npm が 3 パッケージである。

通常の依存更新は月 1 回で十分であり、パッケージごとの PR は細かすぎる。一方、NuGet と
npm の間には同じバージョンへ揃える必要がある依存関係はなく、更新失敗時には
エコシステム単位で原因を切り分けたい。

GitHub のリポジトリ設定では、Dependabot alerts、Dependabot security updates、Grouped
security updates、Dependabot malware alerts を有効にした。通常更新の頻度とまとめ方は、
リポジトリ内の設定ファイルで管理する必要がある。

## 決定

通常の依存更新に Dependabot を使用し、NuGet と npm を別々の月次グループにする。
更新がある月は各エコシステムで 1 本、合計で最大 2 本の PR を作成し、自動マージしない。

通常更新ルールの正は `.github/dependabot.yml` とする。セキュリティ更新は月次を待たず、
GitHub のリポジトリ設定によりエコシステムごとに可能な範囲で集約する。

## 検討した代替

### Renovate を使う

複雑な例外ルール、複数リポジトリの共通設定、Dependency Dashboard を利用できる。しかし、
現在の要件は月次更新とエコシステム単位の集約で満たせる。外部 App のインストールまたは
セルフホストを追加する必要がない Dependabot を採用する。

### NuGet と npm を 1 本の multi-ecosystem PR にまとめる

通常更新を月 1 本まで減らせる。しかし、NuGet と npm の更新を同期させる関係がなく、
失敗時にどちらのエコシステムが原因かを切り分けにくくなるため採用しない。

### 依存パッケージごとに PR を作る

更新ごとの影響を最も切り分けやすい。しかし、月次更新としては PR が細かくなりすぎるため
採用しない。

## 結果

- 通常更新を全エコシステムで 1 本の PR にまとめることはできない
- 更新がある月は通常更新 PR が最大 2 本作成される
- 同じエコシステム内ではメジャー、マイナー、パッチ更新を同じ PR に含めるため、1 件の
  更新失敗が同じグループの他の更新を止める可能性がある
- Dependabot PR は自動マージされず、内容確認とマージ操作が必要になる
- GitHub 側のセキュリティ設定はリポジトリの Git 履歴では強制できず、設定変更による
  ドリフトをコードレビューでは検出できない
- Renovate 固有の Dependency Dashboard や高度な設定共有は利用できない

## 再評価のサイン

- メジャー更新と非メジャー更新を同じ PR で扱うことが継続的な切り分け負担になった
- NuGet と npm を同期して更新する依存関係が追加された
- エコシステムごとに複雑な更新周期や例外ルールが必要になった
- 複数リポジトリで共通設定や Dependency Dashboard が必要になった
- GitHub 側の設定ドリフトが実際に発生し、リポジトリ内での強制が必要になった
