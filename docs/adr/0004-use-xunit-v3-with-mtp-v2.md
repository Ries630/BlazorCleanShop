# ADR-0004: .NET 10 と xUnit v3、Microsoft Testing Platform v2 を採用する

- ステータス: 承認済み
- 日付: 2026-03-30
- 関連: [Issue #3](https://github.com/Ries630/BlazorCleanShop/issues/3)、[当初の設計会話](https://claude.ai/share/081f3e76-b272-49f4-9f1c-de15f8b0b5d4)

## 背景

ユニットテストはこのプロジェクトの主な学習目的であり、Domain 層と Application 層を
中心に TDD を実践する。りーすさんには xUnit の利用経験があり、新規プロジェクトでは
最新の安定版を積極的に使う意向があった。

当初は .NET 8、xUnit v2、VSTest で開始する案も挙がったが、りーすさんが最新の LTS である
.NET 10 と xUnit v3 を選択した。その前提で Microsoft Testing Platform（MTP）の v1 と
v2 を比較し、新規プロジェクトで従来の VSTest 互換性を維持する必要がないことを確認した。

## 決定

.NET 10 と C# 14 を使用し、テストフレームワークには xUnit v3、テスト実行基盤には
Microsoft Testing Platform v2 を採用する。テストプロジェクトは
`xunit.v3.mtp-v2` を参照し、MTP の実行可能プロジェクトとして構成する。

テストダブルが必要なユニットテストでは Moq を使用する。

## 検討した代替

### .NET 8、xUnit v2、VSTest で開始する

既存のツールや情報を利用しやすい安定した構成である。しかし、最新の LTS と新しい
テスト実行基盤を学ぶという意向に合わないため採用しない。

### xUnit v3 と MTP v1 を使う

従来の構成との互換性を残せる。一方、新規の .NET 10 プロジェクトではその互換性を
必要とせず、MTP v2 に対応した `dotnet test` と実行モデルを使うため採用しない。

## 結果

- VSTest を前提とするテストアダプターや実行手順は利用できない
- テストプロジェクトはライブラリではなく実行可能ファイルとして扱われる
- CI、IDE、周辺ツールにも MTP v2 を扱えることが必要になる
- .NET 10 より前の SDK や xUnit v2 に戻す場合、パッケージ、プロジェクト設定、
  `global.json` とテスト実行手順の変更が必要になる
- Moq を使わないテストダブル方式へ変更する場合、既存のモックを記述し直す必要がある

## 再評価のサイン

- 利用する CI または IDE が MTP v2 を安定して実行できない
- xUnit または .NET SDK のサポート方針が変わり、現在の組み合わせが非推奨になった
- Moq では表現しにくいテストが増え、別のテストダブル方式が必要になった
