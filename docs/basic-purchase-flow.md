# 基本購入フロー

この文書を、商品閲覧から注文照会までのユースケースとビジネスルールの正とする。
用語の定義は [`CONTEXT.md`](../CONTEXT.md)、アーキテクチャと依存方向は
[`AGENTS.md`](../AGENTS.md) を参照する。

Shopifyは基本購入フローの参照モデルであり、ShopifyのAPIや機能がこのプロジェクトの
仕様になるわけではない。採用範囲と意図的な差分は
[ADR-0012](adr/0012-use-shopify-as-reference-model.md) に記録する。

## 対象範囲

- 未ログイン利用者による商品一覧と商品詳細の閲覧
- ログイン利用者によるカートの表示、追加、数量変更、削除
- ログイン利用者による注文確定
- ログイン利用者による自分の注文履歴と注文詳細の閲覧

商品管理、在庫、決済、配送、税、割引、複数通貨、返品、注文キャンセルは対象外とする。
注文内容の最終確認はUIとApplication層の手順とし、独立したCheckoutモデルは設けない。

## ユースケース

### 商品を一覧表示する

- 認証を必要としない
- 商品単位で表示し、商品名と最も低い商品バリエーション価格を「○円から」と示す
- 商品名の昇順、同名の場合は商品IDの昇順で返す

### 商品の詳細を表示する

- 認証を必要としない
- 商品名、説明、すべての商品バリエーションと価格を返す
- 存在しない商品は「存在しない」とする

### カートを表示する

- 認証を必要とする
- 永続化されたカートがなければ、DBへ書き込まず空のカートを返す
- 各カート項目へ現在の商品名、商品バリエーション名、価格、行小計を付け、見積合計を返す

### 商品バリエーションをカートへ追加する

- 認証を必要とする
- 存在する商品バリエーションと1〜99の数量を受け付ける
- カートがなければ、この操作で初めて作成する
- 同じ商品バリエーションがあれば新しい行を作らず、既存数量へ加算する
- 加算後の数量が99を超える場合は、カートを変更せず拒否する

### カート項目の数量を変更する

- 認証を必要とする
- 存在するカート項目と1〜99の数量を受け付ける
- 存在しないカート項目、0以下または100以上の数量は、カートを変更せず拒否する
- 数量0を削除の意味には使用しない

### カート項目を削除する

- 認証を必要とする
- 対象が存在する場合は削除する
- 対象が存在しない場合も成功とし、同じ削除を繰り返せる

### カートから注文を確定する

- 認証を必要とする
- 空のカートから注文を作成できない
- すべての商品バリエーションと現在価格を再取得してから注文を作成する
- 商品バリエーションが1件でも存在しなければ、注文もカートも変更せず拒否する
- 商品バリエーションと価格を検証した時点のカート内容が、保存時点まで変更されていない場合だけ成功する
- 注文保存とカート項目の削除を同じトランザクションで確定する
- 注文確定と、同じカートへの追加、数量変更、削除、または別の注文確定が競合した場合は、
  先に確定した操作だけを成功させ、もう一方は競合として拒否する
- 失敗時は注文もカートも変更しない
- 作成した注文のID、受付日時、注文明細、小計、合計を返す

### 注文履歴を表示する

- 認証を必要とする
- 認証された利用者が所有する注文だけを、受付日時の新しい順で返す

### 注文の詳細を表示する

- 認証を必要とする
- 注文時点の注文明細から表示し、現在の商品や商品バリエーションを参照しない
- 存在しない注文と、他の利用者が所有する注文は同じ「存在しない」結果にする

## 商品と商品バリエーション

- 商品を集約ルート、商品バリエーションをその配下のEntityとする
- 商品は1件以上の商品バリエーションを持つ
- 商品名と商品バリエーション名は前後空白を除去した値を使用し、空文字を認めない
- 商品の説明は任意とする
- 商品名、商品バリエーション名、説明の最大文字数はDomainルールとして定めない
- 商品名は重複できる
- 同じ商品内の商品バリエーション名は、大文字・小文字を区別せず一意とする
- 選択肢がない単一の商品バリエーションには「標準」という名前を使用する
- サイズや色の選択肢は商品バリエーション名へ平坦化し、OptionとOptionValueは設けない
- 商品バリエーションは商品を介して作成・変更する
- 現時点では販売状態を持たず、存在する商品バリエーションは購入可能とみなす

## 価格と数量

- 通貨は日本円だけを扱い、小数を認めない
- Moneyは0円以上を表現できる
- 商品バリエーション価格は1円以上とする
- カート項目と注文明細の数量は1〜99とする
- 行小計は単価と数量の積、合計は行小計の総和とする
- 税、送料、割引を合計へ加えない
- カート項目は価格を保持しない。カートの金額は表示時点の現在価格による見積もりとする
- 注文確定時に現在価格で再計算し、その単価を注文明細へ保存する

## カート

- ログイン利用者ごとに現在のカートを1つ持つ
- カート項目が保持するのは商品バリエーションIDと数量だけとする
- 同じ商品バリエーションのカート項目は1件だけとする
- 異なる商品バリエーションは、同じ商品に属していても別のカート項目とする
- 注文確定後はカート項目をすべて削除し、同じカートを再利用する

## 注文と注文明細

- 注文はカート内容を受け付けた記録であり、決済完了を表さない
- 注文状態は設けない
- 注文と注文明細は作成後に変更しない
- 注文受付日時はサーバーが1回だけ設定し、UTCで保存する
- 表示時に利用者向けのタイムゾーンへ変換する
- 注文明細には商品バリエーションID、商品名、商品バリエーション名、単価、数量を保存する
- 商品バリエーションIDは注文元を示す履歴値とし、現在の商品バリエーションの存在を必須にしない
- 注文明細から商品や商品バリエーションへの削除連鎖と必須外部キーを設けない
- 行小計と注文合計は保存した単価と数量から計算し、独立して変更可能な値として保持しない
- 人間向けの注文番号は設けず、注文IDを識別子として使用する

## 認証と所有権

- 商品閲覧以外のユースケースは認証を必要とする
- ゲストカートと、ログイン前に選択した商品の引き継ぎは提供しない
- ショッピングコンテキストにCustomer Entityを設けない
- カートと注文はASP.NET Core Identityの利用者IDを不透明な値として保持する
- Domain層はIdentityの型や利用者情報へ依存しない

## 永続化境界

永続化を分離する理由と代償は
[ADR-0013](adr/0013-separate-identity-and-shopping-storage.md) に記録する。

- IdentityはWeb層の`ApplicationDbContext`と`Data/app.db`を使用する
- 商品、カート、注文はInfrastructure層の`ShoppingDbContext`と`Data/shop.db`を使用する
- それぞれのDbContextが独立したマイグレーションを持つ
- IdentityとShoppingの間に外部キーと分散トランザクションを設けない
- Shopping DBにはIdentityの利用者IDだけを保存する
- 注文追加とカート消費は同じ`ShoppingDbContext`と保存境界で原子的に確定する
- Application層はEF Coreへ直接依存せず、保存境界をApplication層のインターフェースとして扱う

## 再評価条件

- 商品管理を追加する場合、販売停止と商品バリエーション削除時の扱いを決める
- サイズや色の組み合わせを個別に扱う場合、OptionとOptionValueの導入を検討する
- 決済または配送を追加する場合、Checkoutと注文状態を導入するか再評価する
- 税、割引、複数通貨を追加する場合、価格計算とMoneyの責務を再評価する
- ゲスト購入を追加する場合、カート所有者とログイン時の引き継ぎを再評価する
- 問い合わせ対応で人間が読み上げる識別子が必要になった場合、注文番号を追加する
